# Issue: Open redirect in auth callback

**Issue ID:** `ISS-20260730-002`
**Source:** Audit (H8)
**Tier:** 0 (Emergency)
**Status:** `in_progress`
**Assigned To:** Repair Agent
**Created:** 2026-07-30

---

## Description

The `next` query parameter in `auth/callback/route.ts` is not validated. An attacker can craft a URL like `/auth/callback?next=https://evil.com` and when the auth flow completes, the user will be redirected to an external malicious site. This is a phishing vector.

---

## Location

- **File(s):** `web/app/auth/callback/route.ts` (line 9)

---

## Severity

| Dimension | Value | Rationale |
|-----------|-------|-----------|
| Impact | `high` | Phishing attack vector — trust redirect |
| Likelihood | `likely` | Easy to exploit, visible URL parameter |
| Priority | `P0` | Security-critical |

---

## Expected Behavior

The `next` parameter should only allow relative URLs (starting with `/`) and should not allow protocol-based URLs like `https://`.

---

## Actual Behavior

Line 9: `const next = searchParams.get('next') ?? '/'` — any value is accepted without validation.

---

## Acceptance Criteria

- [ ] Absolute URLs (`https://...`) are rejected
