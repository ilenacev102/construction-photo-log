# Issue: `.gitignore` missing `.env*` — risk of secret leakage

**Issue ID:** `ISS-20260730-001`
**Source:** Audit (C1)
**Tier:** 0 (Emergency)
**Status:** `in_progress`
**Assigned To:** Repair Agent
**Created:** 2026-07-30

---

## Description

`.gitignore` at project root does not include `.env*` patterns. The file `.env.local` exists with live `SUPABASE_SERVICE_ROLE_KEY` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. If anyone runs `git add .` or `git add -A`, these secrets will be committed to the repository.

---

## Location

- **File(s):** `.gitignore` (root), `web/.env.local` (contains secrets)

---

## Severity

| Dimension | Value | Rationale |
|-----------|-------|-----------|
| Impact | `critical` | Complete database compromise if committed |
| Likelihood | `possible` | Easy mistake during development |
| Priority | `P0` | Security-critical |

---

## Expected Behavior

`.gitignore` includes `.env*` to prevent any `.env` files from being committed. Secrets are loaded from Vercel environment variables or a local `.env.local` that git ignores.

---

## Actual Behavior

`.gitignore` only ignores Python cache patterns. `.env.local` with production secrets is unprotected.

---

## Acceptance Criteria

- [ ] `.gitignore` includes `.env*` and `.env.local` patterns
- [ ] `git check-ignore .env.local` returns exit code 0 (file is ignored)
- [ ] No other `.env*` files should be tracked
- [ ] All existing tests still pass
- [ ] No new lint/type errors introduced
